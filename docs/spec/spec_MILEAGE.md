# Spec MILEAGE

## Входит

- Бизнес-решение по валидному пробегу автомобиля на границе `400000` км.
- Сохранение более строгого решения, уже полученного по LTV.
- Сохранение текущей ошибки входных данных для отсутствующего пробега и значений выше действующего валидационного предела.

## Не входит

- Изменение формулы и порогов LTV.
- Изменение правил VIN, возраста автомобиля, суммы и срока заявки.
- Изменение схемы БД, интерфейса формы и формата ответа сервиса.
- Пересмотр действующего максимального валидного пробега `500000` км.

## Требования и критерии приёмки

### REQ-MILEAGE-01 — допустимая сторона бизнес-порога

Валидный пробег не больше `400000` км сам по себе не меняет решение, рассчитанное по действующим правилам LTV. Источник числа: `docs/intent/intent_MILEAGE.md`, ответ в интервью.

- **AC-MILEAGE-01** (REQ-MILEAGE-01): Given заявка, для которой LTV даёт `approve`, и пробег `399999` км; When заявка оценивается; Then решение остаётся `approve`. Источник числа: промпт ДЗ.1 как значение непосредственно перед согласованной границей `400000`.
- **AC-MILEAGE-02** (REQ-MILEAGE-01): Given заявка, для которой LTV даёт `approve`, и пробег ровно `400000` км; When заявка оценивается; Then решение остаётся `approve`. Источник числа: `docs/intent/intent_MILEAGE.md`, ответ в интервью.

### REQ-MILEAGE-02 — ручное рассмотрение выше бизнес-порога

Валидный пробег выше `400000` км переводит только решение `approve` в `review`. Источник числа: `docs/intent/intent_MILEAGE.md`, ответ в интервью.

- **AC-MILEAGE-03** (REQ-MILEAGE-02): Given заявка, для которой LTV даёт `approve`, и пробег `400001` км; When заявка оценивается; Then итоговое решение — `review`, а одобренный лимит равен `0`. Источник числа: `docs/intent/intent_MILEAGE.md`, ответ в интервью; нулевой лимит — действующее поведение `review` в `AssessmentService`.

### REQ-MILEAGE-03 — приоритет более строгого решения

Правило пробега не смягчает уже полученные по LTV решения `review` и `reject`; порядок строгости — `reject` → `review` → `approve`. Источник: `docs/intent/intent_MILEAGE.md`, ответ в интервью.

- **AC-MILEAGE-04** (REQ-MILEAGE-03): Given пробег `400001` км и LTV-решение `review`; When заявка оценивается; Then итог остаётся `review`. Источник числа: согласованная первая точка выше порога из `docs/intent/intent_MILEAGE.md`.
- **AC-MILEAGE-05** (REQ-MILEAGE-03): Given пробег `400001` км и LTV-решение `reject`; When заявка оценивается; Then итог остаётся `reject`. Источник числа: согласованная первая точка выше порога из `docs/intent/intent_MILEAGE.md`.

### REQ-MILEAGE-04 — отсутствующий пробег

Пустой или неизвестный пробег, представленный отсутствующим полем `mileage`, остаётся ошибкой входных данных и не превращается в `review`. Источник: `docs/intent/intent_MILEAGE.md`, ответ в интервью и текущее поведение валидатора.

- **AC-MILEAGE-06** (REQ-MILEAGE-04): Given в заявке нет значения пробега; When заявка валидируется; Then возвращается ошибка поля `mileage`, а решение `approve` / `review` / `reject` не рассчитывается. Числовых значений нет; источник поведения: `docs/intent/intent_MILEAGE.md`.

### REQ-MILEAGE-05 — независимый валидационный предел

Действующий допустимый диапазон пробега от `0` до `500000` км включительно сохраняется независимо от бизнес-порога `400000` км. Источник чисел: `backend/config/rules.php` и `docs/intent/intent_MILEAGE.md`.

- **AC-MILEAGE-07** (REQ-MILEAGE-05): Given валидная заявка с пробегом `500000` км; When заявка валидируется и оценивается; Then пробег принимается как валидный и применяется бизнес-решение `review`, если LTV дал `approve`. Источник числа: `backend/config/rules.php`, действующий `max_mileage_km`.
- **AC-MILEAGE-08** (REQ-MILEAGE-05): Given заявка с пробегом `500001` км; When заявка валидируется; Then возвращается ошибка поля `mileage`, а не решение `review`. Источник числа: первое целое значение выше `max_mileage_km = 500000` из `backend/config/rules.php`.

## Статус Open questions из intent

- Граница `400000` км — **закрыт** ответом пользователя: значение включено в допустимую сторону.
- Пустой или неуказанный пробег — **закрыт** ответом пользователя: остаётся ошибкой входных данных.
- Приоритет `reject` — **закрыт** ответом пользователя: правило пробега не смягчает более строгое решение.
- Пересмотр максимального валидного пробега `500000` км — **перенесён** в отдельное решение риск-менеджмента; в этой задаче предел не меняется.
